# Task 003 — Motion & interaction — progress log

## Status: completed

## What was built

`src/scripts/motion.ts` — the only file this task owns. GSAP 3 + ScrollTrigger,
registered explicitly (`gsap.registerPlugin(ScrollTrigger)`), with the
reduced-motion split done via `gsap.matchMedia()`. Implements exactly the four
animations in epic.md §8.3 and nothing else (no counters, no scroll-linked
progress spine, no parallax, no pinned sections, no scrubbed timelines, no
text scrambles, no background animation).

All animation from-states (`opacity: 0`, `y: 16/20`) are set via `gsap.set()`
in JS only — never in CSS. Nothing in this file touches a stylesheet. With
JavaScript disabled or broken, every element renders in its natural, fully
visible DOM state and every link works (criterion 41). Under
`prefers-reduced-motion: reduce`, `gsap.matchMedia()` simply never registers
the animation block, so — again — nothing is ever hidden (criterion 42).

## Data-attribute contract (for task 002 / whoever builds the markup)

| Attribute | Where | Behaviour |
|---|---|---|
| `[data-animate="hero"]` | Hero section container | Marks the container whose `[data-animate-item]` descendants animate on page load (no ScrollTrigger). |
| `[data-animate-item]` | Inside a `[data-animate="hero"]` container | Each one is a beat in the on-load staged sequence, **in DOM order**: fade + 16px rise, 0.5s duration, 0.06s stagger, `power2.out`. Intended order per §8.3: `h1` → lead paragraph → meta line → CTA row. **Group a multi-element row (e.g. the CTA row's "Email me" button + "View CV" + LinkedIn/GitHub links) inside one wrapper element carrying this attribute**, so the row moves as a single beat, not one animation per link. |
| `[data-animate="section"]` | Any section heading or body block | Fade + 16px rise on scroll enter, 0.45s, `power2.out`, own `ScrollTrigger` per element (`start: "top 85%"`, fires once). No stagger — apply independently to each heading/paragraph that should animate. |
| `[data-animate-stagger]` | Wrapper around a group of project cards (e.g. the projects grid) | One `ScrollTrigger` on this container; when it fires, all `[data-animate="card"]` descendants inside it animate together. |
| `[data-animate="card"]` | Each project card | Fade + 20px rise, 0.5s, 0.08s stagger between cards, `power2.out`. Must be nested inside a `[data-animate-stagger]` container to animate — a card with this attribute but no stagger ancestor is silently skipped (the container query finds nothing). |
| `[data-animate="fade"]` | CV page entries/headings | Fade only, **no transform** — "it is a document" (§8.3). Same scroll-trigger mechanics as `"section"` (`start: "top 85%"`, once), 0.5s duration. |

Notes for integration:
- These are independent selectors, not a class hierarchy — an element can only
  usefully carry one `data-animate` value (don't combine `"section"` and
  `"card"` on the same node).
- `[data-animate-item]` is a *different* attribute from `data-animate` and is
  only meaningful nested inside `[data-animate="hero"]`.
- All matching is done with `querySelectorAll`, so nesting depth doesn't
  matter (e.g. cards can be direct children or deeper descendants of the
  `[data-animate-stagger]` container).

## Init function — call signature

```ts
import { initMotion } from '../scripts/motion';
// or: import initMotion from '../scripts/motion'; (default export, same function)

initMotion();          // scopes to `document` (default)
initMotion(someRoot);  // optionally scope to a subtree (ParentNode)
```

Call once per page, any time after the animated elements exist in the DOM —
e.g. from a plain `<script>` (module) near the end of the layout, or inline in
each page/layout that needs motion. Safe to call more than once in the same
document load; repeat calls are no-ops (guarded by a module-level flag). This
is a static multi-page site (no client-side routing), so no teardown/cleanup
API was built — each page load gets a fresh JS context anyway.

## Parameters used (all within epic.md §8.2 ranges, using the spec defaults)

- Hero on-load: 0.5s duration, 16px rise, 0.06s stagger.
- Section on-enter: 0.45s duration, 16px rise, no stagger.
- Cards on-enter: 0.5s duration, 20px rise, 0.08s stagger.
- CV fade-only: 0.5s duration, no offset.
- Easing: `power2.out` everywhere. `ScrollTrigger` `start: "top 85%"`,
  `once: true` on every trigger (never reverses on scroll-up). Only
  `transform` (via GSAP's `y`) and `opacity` are ever animated.
- `will-change` is set to `"transform, opacity"` only for the duration of each
  tween (`onStart`) and reset to `"auto"` on `onComplete`.
